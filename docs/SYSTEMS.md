# 系统状态页（`/console/system`）

> 只读运维视图：现在是什么状态，为什么是这个状态。不提供「让它变成另一个状态」的按钮。

## 为什么只读

安装、升级、回滚、卸载会**写文件并执行包内容**。把这几件事搬到网页上，
等于把 RCE 面挪进后台 —— 一个 CSRF 或一次误点就能替换整站代码。

所以这一页的价值不是「省掉 SSH」，而是：

- 运维不必为了回答「现在什么版本 / 库通不通 / 有没有未应用的迁移」去跑命令；
- 出问题时能截图给不在这台机器上的人；
- 页面本身**不能**改变任何状态，误点的后果为零。

命令行仍然是唯一的写入口，这一条写在页面底部的边界说明里，不是藏在文档里。

## 读什么

| 接口 | 回答什么 |
| --- | --- |
| `system.health` | 数据库 / storage / 主题三项 check，分级 ok / degraded / down |
| `system.info` | core 版本、PHP、接口数、契约数、数据库模式、主题、headless |
| `system.layers` | 系统层的装配顺序 |
| `system.contracts` | 契约与覆盖台账 |
| `lifecycle.units` | 已装单元、版本、状态、是否有备份 |
| `release.status` | 站点版本、schema 批次、**未应用的迁移清单** |

## 逐项降级，不整页消失

取数不是「全成功才渲染」。健康检查挂了，版本与装配顺序仍然要能看到 ——
否则「页面打不开」和「站点真的坏了」会变成同一种症状，而这正是运维最需要区分的两件事。

实现上每个接口单独 try，失败记一条错误，页面顶部给「有 N 项没取到」，
其余块照常渲染。`SystemsQuery::fetch()` 返回的 `errors` 就是这个账本。

## 数字不许写死

页面上的契约数、装配层数、迁移数全部来自接口返回值，不复制常量。
`55` 组守卫专门比对这三处与 `system.*` 的一致性 —— 写死一个数字，
下次新增系统层时页面就会开始说谎，而且没人会发现。

## 健康状态不是恒定 ok

`health()` 在 v0.20 之前第一行就是 `'status' => 'ok'`。现在逐项检查：
任一 `down` → 整体 `down`，其余非 `ok` → `degraded`。

页面把三项 check 原样列出（`database=ok(mysql) · storage=ok(writable) · theme=ok(glass)`），
因为「整体降级」不告诉你是哪一项。同时区分「降级」与「不可用」：
降级还能服务，不可用应该摘流量，运维动作完全不同。

## 未应用的迁移要显眼

`release.status.pending` 是这一页最有用的字段：它直接对应「代码更新了但库没跟上」。
只要非空，页面就是 warn 色，并列出前三个文件名。

反过来，空的时候也要说「没有未应用的迁移」，而不是不给这块 —— 沉默会被读成「没检查」。

## 已知缺陷（本版不修）

`logs.query` 的 `total` 字段算错了：实现先 `array_slice()` 再 `count()`，
所以 `total` 实际是「返回了几行」，不是「文件里共有几行」。想让它变成
「共 2000 行，显示最近 20 行」需要改系统层的返回结构，属于日志页那一版的事。
这一页不消费 `logs.query`，因此不受影响。

## 边界

- 不提供 install / upgrade / rollback / uninstall：见上。
- 不做日志查看：`logs.query` 零消费，单独一版，且要先修 `total`。
- 不做插件启用 / 停用：同样写文件。
- 不展示 `permission_audit` 历史：那在决策轨迹页的边界里，需要新接口。
- 页面声明 `system.config.read`：进程、路径、迁移清单都会暴露部署结构，
  比授权信息更敏感，editor 不在其列。

## 守卫

`tests/groups/55-systems-runtime.php` 从 HTTP 面验证 6 条：匿名 401、
五类块都在、契约数与层数来自接口、健康标签与接口一致且逐项列出、
迁移清单与 `release.status` 一致、页面没有写表单且 POST 被拒。
