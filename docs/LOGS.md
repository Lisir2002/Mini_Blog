# 系统日志页（`/console/logs`）

> 只读视图，消费 `logs.query`。本页不写任何东西，因此没有表单票据。
> 它同时也修掉了 `total` 语义的错误 —— 这个缺陷让「共 2000 行」永远显示成 2000 之外的那个数。

## 1. 为什么是单独一页

日志是「事后证据」，站点上此前只有 `logs.query` 接口和命令行。运维要回答的问题很具体：
**今天几点开始出错的、错误之前紧邻的几行是什么**。这需要按日期看尾部，而不是一屏看板。

页面的三条硬边界写进了界面本身：

- 只读某一天的**尾部**，不做跨天检索、不做全文搜索、不读归档；
- 页面不拼 `storage/logs` 路径 —— 文件按天平铺是日志系统的实现细节，页面只消费接口给的 `dates`；
- 日志内容原样呈现，页面不解释、不改写、不合并重复行。

## 2. 接口语义（v0.40 修正）

`GET /api/v1/logs/query?date=YYYY-MM-DD&limit=20`

| 字段 | 含义 | 易错点 |
| --- | --- | --- |
| `exists` | 该日期是否有日志文件 | `false` 是「那天没跑过」，不是「空日志」 |
| `total` | 文件内非空行总数 | **不是**本次返回行数 |
| `returned` | 本次返回行数（≤ `limit`） | 与 `total` 一起看才知道看的是全部还是尾巴 |
| `truncated` | `total > returned` | 截断必须显式声明，不能靠调用方自己减 |
| `lines` | 文件尾部 `limit` 条，按时间正序 | 取尾部而非头部：最新的事故在末尾 |
| `dates` | 可查询日期，倒序，最多 60 天 | 页面据此渲染日期切换，不扫目录 |

### 修掉的缺陷

原实现：

```php
$lines = array_slice(array_values($lines), -$limit);
return ['date' => $date, 'lines' => $lines, 'total' => count($lines)];
```

`total` 是切片之后数的，所以它恒等于 `min(limit, 文件行数)`。界面若拿它当「共多少行」，
就会把 2000 行的一天说成 20 行 —— 而且看起来完全正常，没有任何报错。

修正后 `total` 在切片**之前**计算，并补 `returned` / `truncated` / `exists` / `dates`。
这是兼容性变更（只追加字段、修正一个从未正确过的语义），接口主版本不变，变更记录写在
`API-LOG-001` 的 changelog 里。

## 3. 四种「没有内容」必须分开

| 状态 | 触发条件 | 页面呈现 | 为什么不能合并 |
| --- | --- | --- | --- |
| `missing` | 该日期没有日志文件 | 「这一天没有日志文件」+ 最近有日志的日期 | 与「空文件」的处置完全不同：前者去查站点那天是否运行过 |
| `empty` | 文件在，`total = 0` | 「文件存在，但一行也没有」 | 文件被创建说明目录可写，问题在写入侧 |
| `filtered-empty` | 窗口内有行，但没有该级别 | 「本次窗口里没有 ERROR」+ 文件总行数 | 说成「今天没有错误」是最容易被相信的谎 |
| `unavailable` | 接口抛错 / 文件不可读 | 503 + 原因 | 读不到不能长得像「没有」 |

参数错误（日期格式、不存在的日期、非允许条数、拼错的级别）一律 **422**，
不静默回退成「今天 / 20 / 全部」。回退会让人以为自己查的是输入的那个条件。

## 4. 页面结构

1. **窗口说明** —— `日期 · 共 N 行`，截断时明说「更早的 M 行没有取」；
2. **查询表单** —— `date` + `limit`（GET，无票据：不写任何东西）；
3. **级别筛选** —— 全部 / ERROR / WARN / INFO / DEBUG / OTHER，每项带**窗口内**计数；
4. **表格** —— 时分秒 / 级别 / 正文；认不出的行标 `OTHER` 并保留原文，不丢弃；
5. **原始行** —— `raw=1` 时附 `pre` 区块，用于对照解析是否吃掉了内容；
6. **日期切换** —— 取接口 `dates`，最近 14 天；
7. **边界说明** —— 上面三条硬边界，写在页面上而不是只写在文档里。

## 5. 只读与写方法

日志页没有 `form_ticket`。带 Cookie 的 POST 在守卫层就被 401 挡回 ——
Cookie 只用于页面读取，写操作必须用请求头令牌（这是 v0.9 起的 CSRF 边界，不因本页改变）。
带 Bearer 令牌的 POST 才会走到页面自身，返回 `405` + `Allow: GET, HEAD`。

## 6. 测试

`tests/groups/56-logs-runtime.php`（11 条）：

- 接口语义：`total` / `returned` / `truncated` / `exists` / `dates`；
- 页面四态：`truncated` / `filtered-empty` / `missing` / `empty`；
- 过滤计数只在窗口内，且文案带文件总行数；
- 参数错四类各 422；
- `raw=1` 输出未改写内容；
- 只读：Cookie POST 401、Bearer POST 405。

测试自建 `2002-03-04.log`（30 行）与 `2002-03-05.log`（空），结束后删除，
不依赖真实日志，也不污染它们。

## 7. 边界

- 不做跨天 / 关键字检索：需要新的接口与索引，属于独立一版；
- 不做归档与轮转：当前 `FileLogger` 按天写、不清理，长期运行要加保留策略；
- 不做级别写入侧约束：`LoggerInterface::log()` 接受任意字符串，页面只能照实显示；
- 不读数据库里的审计表：那是决策轨迹页的边界。
