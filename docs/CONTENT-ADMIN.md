# 内容管理台

`/console/content` 回答「这个站点能不能自己用」：此前 `draft / review / published / archived`
四态与 `transition / delete / restore / purge / trash` 五个接口都齐全，但页面上一个字都写不了，
只能 curl。

它是页面写表单的**完整形态**：CSRF、一次性票据、权限裁剪、乐观锁、PRG、
失败绝不 303 —— v0.32 的评论编辑只是小规模试点，这里全部齐备。

## 写路径：票据而不是 Cookie

页面守卫对非 GET 不读 Cookie（CSRF 边界）。浏览器表单也带不了 `Authorization`。
所以身份只能由 GET 时签发的短期票据证明：

| 阶段 | 身份来源 |
| --- | --- |
| GET 列表 | 页面守卫已裁决的身份（Cookie / Bearer 均可） |
| GET 票据 | 服务端签发，绑定 `content.read` + `/console/content`，20 分钟 |
| POST 操作 | 守卫验签取回身份，再调用同一个生命周期接口 |

票据的权限点必须与页面声明逐字一致：审核队列的票据拿到内容页提交会被拒（反之亦然）。
`pages/Shared/ConsoleTicket.php` 是两页共用的一份实现，避免「两套票据、两种过期语义」。

## 权限裁剪：不给假按钮

页面门槛是 `content.read`（author 也能进），但动作各自需要权限：

| 动作 | 权限点 |
| --- | --- |
| 发布 / 转草稿 / 归档 | `content.publish` |
| 移入回收站 / 恢复 / 彻底删除 | `content.delete` |

页面先问一次 ACL，没有权限的动作**不渲染按钮**，改为一句说明缺哪个权限点；
接口层再判一次 —— 前一次是为了不给假按钮，后一次才是真边界。
author 因此能看列表、能读文章，却看不到发布与删除入口。

## 回收站不是第二个列表

- 回收站里的文章 `status` 原样保留（草稿仍是草稿），所以它能被恢复成删除前的样子；
- 恢复只清 `deleted_at`，**不会顺手发布** —— 那会把「删错了」变成「偷偷上线」；
- 彻底删除只对回收站里的文章生效，且要求人手写出 slug 作为二次确认。
  布尔 `confirm=true` 会被前端默认填上，写 slug 是没法顺手点过去的动作。

两个视图的空态文案也分开：列表空 = 还没写过文章；回收站空 = 没删过东西。
共用一句「暂无内容」会让读者无法判断是哪一种。

## 呈现

复用 `admin` 布局与通用区块协议：`notice`（计数 / 截断 / 失败）、`links`（视图切换）、
`form`（每行一个动作表单，带 `_form_ticket` 与 `slug` 隐藏字段）。
`pages/*` 仍不产 HTML / CSS / JS。

## 边界

- 不做正文编辑器：写表单 + 校验 + 权限判定同时变复杂，值得单独一版；
- 列表上限 20 条，`total` 更大时显式声明「未列全」，不做无限滚动；
- 状态迁移仍由系统层裁决，页面只提供三个可达方向（发布 / 草稿 / 归档）。

## 证据

- `46` 组：匿名 401、管理员列表与票据、无票据 401、迁移落库、未知动作 422、
  回收站往返、确认串不符 422、跨页票据被拒、author 看不到按钮。

## 只看置顶（v0.56）

`content.posts` 的 `pinned` 筛选器此前只被当作排序展示字段：列表按 pinned 与
weight 排序，却从不按置顶过滤。v0.56 补上「只看置顶 / 全部文章」视图：取数层
`live(..., pinned)` 透传并带出列表级标记，按 weight 倒序、不混进游标分页；
`ContentAdminPinned` 集中生成导航、说明、空态、scope、hidden 与 PRG href。
行表单、排期表单、推荐位表单的 hidden 都回传筛选状态，PRG 后仍留在原视图，
不会「在只看置顶里改一次权重就被弹回全部文章」。空态区分「筛选结果为零」与
「站点没有文章」，排序标题在置顶视图改说「按权重倒序」。
