# 统计看板：把「现在发生了什么」放到运维眼前

v0.26 建了统计系统：三类指标、小时聚合、四通道采集、`durable` / `degraded` / `last_error`。
它能回答「多少请求、错多少、多慢、谁被调得多」，但只有 JSON 接口与 CLI ——
**运维不 curl 就看不见。** 这一轮把它接到控制台上。

## 一句话结构

```
/console/stats  ──▶  StatsPage
                       │  权限：page admin + metric.read（复用 admin 布局）
                       ├─ StatsQuery::collect()  ──▶ stats.overview / series / operations / catalog
                       ├─ StatsQuery::board()    ──▶ 结构化 blocks（notice / links / table / chart）
                       └─ 主题 blocks.php        ──▶ 纯 CSS 柱状图，零脚本
```

**零新增接口、零新增系统层、零新增布局槽位。** 页面只做三件事：取数、判定状态、组装区块。

## 核心不变量：0 不能冒充健康

这是整轮唯一真正重要的事。四种情况在旧页面上会渲染成同一张「一排 0」的空看板：

| 情况 | 判定 | 页面行为 |
| --- | --- | --- |
| 采集器内存驱动（`durable=false`） | `degraded` | 醒目警示：数字只代表本次运行，不能当全站流量 |
| 写聚合失败过（`degraded` / `last_error`） | `degraded` | 警示 + 暴露最近错误 |
| 窗口内无采样 | `empty` | 说明「采集器正常，只是这段时间没请求」 |
| 接口执行失败 / 库不可用 | `unavailable` | **503**，不渲染任何区块 |

`StatsState::assess()` 是这四种判定的唯一入口，`StatsState::unavailable()` 是失败态的唯一入口。
两者都由 `40` 逐项断言，不靠「看起来像」。

特别注意 `requests === 0 && !hasPoints` 才判 `empty`：有请求但序列点为空
（例如序列被截断）不能说成「没有采样」。

## 窗口白名单

`window` 只接受 `1h`~`30d` 形式（小时位最多三位，覆盖 `720h`）。非法值显式 **422**，
不静默回落到 `24h` —— 「我选了 7 天，页面悄悄给我 24 小时」比报错更糟。

## 柱状图：纯 CSS，零脚本

`StatsQuery::chartPoints()` 把序列点换算成 `ratio`（0~1）：

- `max = 0` 时全部返回 `0.0`，**绝不除零**制造 `NaN` / `Infinity`；
- 非零值给最小可见高度 `0.03`，避免「有数据却看不见」；
- 脏时间标签原样保留，不伪装成今天；
- 序列被截断时区块带 `truncated` 标记，页面在标题旁声明。

模板只用 `style="height: N%"` 驱动柱高，无 JS、无外部资源。

## 区块协议

`blocks.php` 新增两种类型，两款元主题逐字同源：

| 类型 | 用途 | 机器标记 |
| --- | --- | --- |
| `notice` | 采集器状态条 | `data-stats-state` |
| `chart` | 纯 CSS 柱状图 | `data-chart-points` / `data-chart-empty` / `data-chart-truncated` |

`table` 沿用既有协议，承载流量与耗时、接口排行、采集器与字典三块。

## 权限

`page.json` 声明 `access.auth = admin` 且 `access.permission = metric.read`。
两级裁决与 API 同源：认证器判「你是谁」，权限决策器判「你能不能看统计」。
未授权一律 fail-closed。

这带来一个有用的副作用：**数据库不可用时权限层先拒绝，页面拿不到数据也不会渲染假数字。**
宁可不给，也不给错的。

## 窗口切换：链接组，不是下拉框

窗口是 `?window=` 参数，此前页面上没有入口 —— 读者只能看到默认 24 小时。
v0.32 把它做成 `links` 区块协议：

- 三项预设（24h / 7d / 30d）都是普通 `<a href>`，可分享、可前进后退、无脚本可用；
- 当前项带 `aria-current="page"`，不单靠颜色表达；
- 手传非预设值（如 `12h`）时**追加一项并注明「非预设」**，不把用户悄悄拨回 24h ——
  否则页面显示的窗口与地址栏里的参数不一致，读者会以为自己的请求被忽略；
- 非法值仍然 422，失败页不渲染链接组（没有数据可切）。

`StatsBlocks::windowLinks()` 是纯函数，`40` 直接穷举 active 唯一性与非预设追加，
`40b` 再从真实 HTML 里核对链接、`aria-current` 与 active 迁移。

## 实现中抓到的两个真问题

1. **`window` 正则只允许两位数字**，`720h`（30 天上界）被误拒。
   边界值必须和声明的范围一起测，否则「上界写了 720h，实际只到 99h」。
2. **容器不允许低优先级覆盖已注册的高优先级实现**：本想用内存驱动替换采集器来测降级，
   结果被「契约冲突」拦下。硬绕会让守卫本身变脆，于是把降级态交给 `40` 的纯逻辑覆盖，
   `40b` 改测「库不可用时 fail-closed、不渲染任何图表」—— 这才是端到端真正会发生的事。

## 边界

- 页面不写 SQL、不认识表名，全部经 `stats.*` 接口。
- 不做实时刷新：没有轮询，没有 WebSocket。要看最新数据就刷新页面。
- 分位耗时仍是固定桶近似，页面标注 `approx`，不假装精确。
- 排行与序列都有条数上限，截断一律声明，`total` 仍是真值。

## 可重跑证据

```bash
php tests/run.php        # 40 / 40b：纯逻辑 + 真实权限与主题（含窗口链接组）
php tools/metrics.php verify
```

`40` 覆盖窗口白名单、柱状图比例边界、四态判定、不可用态、区块组装、清单声明与区块协议；
`40b` 覆盖匿名拒绝、admin 渲染、非法窗口 422、合法窗口生效、Headless 纯数据，
以及「库不可用时不显示一排列全 0」。

## 维度下钻（v0.56）

看板此前固定取全站按小时的请求序列，`stats.series` 的 `dimension` 是契约预留
却没有任何页面入口。v0.56 接上它，关键是**下钻链接必须构造完整可命中的维度串**：
后端把维度串按标签名字母序规范化后做等值比较，此前真实采集的 `api_calls` 带
`operation` 与 `code` 双标签、`http_requests` 带 `method` 与 `status` 双标签，
契约旧示例 `operation=content.posts` 少了 `code`，永远查不到采样。

因此页面按 `stats.catalog` 声明的标签白名单校验「必须带齐全部标签」，从
`stats.operations` 排行的真实 operation 反推完整串；缺标签 / 非法键 / 未知指标
显式 422，合法但无采样的维度单独说明「该维度窗口内没有采样」，不冒充站点没流量
或采集器故障。字典没声明 `api_calls` 或标签超出可反推范围时不生成入口。
`72` 组锁纯函数与口径，`72b` 组在真实 MariaDB 上先发接口请求落下采样，再验证
下钻确实命中、GET 链接可分享、四类非法参数 422 与空采样三态区分。
