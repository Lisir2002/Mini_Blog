## 2. 功能与适用场景

撤销当前请求所用令牌；若它是会话令牌则同时清除 wx_session Cookie。

**适用场景**：后台退出登录；设备丢失时远程吊销浏览器会话。

**实现备注**：只撤销 kind=session 的令牌，不会误伤同用户的 API 脚本令牌。响应总是带一条清除 Cookie 的 Set-Cookie；重复调用返回 revoked=false 而非报错（幂等语义）。 本接口在清单里显式声明 accept_session=true：允许浏览器用 HttpOnly 会话 Cookie 直接调用，其余接口一律不接受会话令牌作为凭据。 v0.47 起浏览器登出经 PageSession 走本接口执行器：与 API 客户端同一套判定，接口不可用时安全层降级直撤并留痕。

## 4. 响应规范

统一信封（自研结构，对齐 RFC 9457 的机器可读错误思想）：

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "request_id": "16 位十六进制",
  "meta": {"api": "API-AUTH-004", "version": "v1", "system": "security"}
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | int | 业务码，`0` 为成功；非 0 为可分支的机器可读错误码 |
| `message` | string | 面向人的简要说明 |
| `data` | any | 成功时的业务数据；失败时恒为 `null` |
| `request_id` | string | 请求标识，来自 `X-Request-Id` 或服务端生成 |
| `errors` | array | 字段级校验明细，仅错误响应出现 |
| `detail` | string | 仅当 `config.api.expose_errors=true` 时出现，禁止在生产开启 |
| `meta` | object | 接口编号、版本、所属系统层 |

**data 字段说明**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `revoked` | `bool` | 是否撤销了一条会话令牌；静态令牌固定为 false |

## 5. 错误码

| 业务码 | HTTP 状态 | 说明 |

| `40101` | 401 | 未认证 |
| `40102` | 401 | 令牌无效或已过期 |
| `40301` | 403 | 无权限执行该操作 |
| `40302` | 403 | 写接口未开放公网访问 |

错误响应形态：`code` 非 0、`data` 为 `null`、`errors` 给出字段级明细。HTTP 状态与业务码严格对应，禁止「200 里塞错误」。
