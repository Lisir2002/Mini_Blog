# 归档 / 标签 / 分类页

> 代码：`pages/Archive/` · `themes/GlassFront/templates/archive.php` · `themes/Glass/templates/archive.php`；接口：`content.posts` / `content.terms`（既有公开接口，本轮零新增）；守卫：`tests/groups/38-archive-pages.php`、`tests/groups/38b-archive-pages-runtime.php`。

v0.28 把分类与标签做成了可穷举的规则，v0.29 把评论互动做成可判定的事实，
但读者侧仍然看不到它们：站内只有首页文章流与文章详情，术语表躺在库里，
标签没有入口、分类没有索引、往期文章只能顺着列表一页页翻。能力齐了，呈现没接上。

这一轮补的是**呈现链路**：归档页、标签云、术语详情。刻意做到
零新增接口、零新增系统层、`core/` 零改动 —— 能力都已经在承载层里，
缺的是把它们组织成读者能点开的页面。

## 1. 落点判定：为什么是独立页 + 主题布局

按三问法，这件事既不需要表、不需要权限点，也不需要新的业务规则，
所以不进系统层；它要声明路由、要产出结构化数据，所以是一个独立页包；
它要输出 HTML，所以由主题新增一个 `archive` 布局槽位。

**页面只产数据，主题只产呈现**（规矩 J）。`pages/Archive/` 里没有一行 HTML、
CSS、JS，也没有 `templates/` 与 `assets/`；文章标题、日期、术语名称、
目标地址都是结构化字段，是否渲染成 `<a>`、长什么样，全部由主题模板决定。

反过来，主题也不碰数据：两款元主题的 `archive.php` 只读渲染器从 payload
收敛出来的变量，不调用接口、不认识 SQL、不自造默认文章。

## 2. 三个视图与数据契约

| 路径 | 视图 | 数据来源 | 产出 |
| --- | --- | --- | --- |
| `/archive` | 归档 | `content.posts`（游标翻到末尾） | 按 `created_at` 的年月分组，每篇带标题链接、日期、术语链接 |
| `/terms` | 标签云 | `content.terms` | 分类与标签两类术语，附已发布文章数 |
| `/term?kind=tag&slug=php` | 术语详情 | 先查术语，再按 `term` + `kind` 筛选文章 | 该术语下的文章列表 |

`content.posts` 单页上限是 100，归档用 `next_cursor` 循环翻到末尾；
达到篇数 / 页数硬上限就置 `truncated`，并把 `shown` 与 `total` 一起交给主题。
`total` 仍是真实总数 —— 截断只声明「本页没有列全」，不改写「一共多少」。

分组是纯函数：时间由调用方注入，脏日期（空串、非法字符串、未来时间）
进「日期未知」桶，绝不会悄悄变成 1970 年 1 月凭空多出一组。

标签云的 `count` 来自 `content.terms` 的 `post_count`，而 `post_count` 与
列表筛选同一套口径（都不含回收站、都不含未到点的定时文章）。守卫逐项比对：
点进某个标签看到的 `total`，必须等于标签云上显示的数字。

## 3. 四种状态必须能被区分

这是本轮最花心思的地方。「看起来没内容」至少要分成四种，混成一种是静默出错：

| 状态 | HTTP | 页面表现 | 为什么不能混 |
| --- | --- | --- | --- |
| 确实没有 | 200 | 显式「暂无已发布文章」/「站点还没有分类或标签」 | 重试没有意义，但站点是健康的 |
| 被截断 | 200 | 显式「此处列出 N 篇，共 T 篇」 | 不假装已经全部列出 |
| 功能不可用 | 503 | 显式「当前为内存降级模式，分类与标签需要 MySQL」 | 「没有标签」和「这个功能在当下不可用」不能长得一样 |
| 参数 / 术语错 | 422 / 404 | 显式「参数不合法」/「术语不存在」 | 拼错的地址不能伪装成一个空标签页 |

`content.terms` 在内存降级下抛 `50101`（v0.28 就定下的规矩：不返回空数组）。
归档页把它当作**旁路失败**：文章归档照常渲染，标签云那块区域留一条显式说明；
而 `/terms` 以术语为主体，直接返回 503 + 失败态。两者共享同一份状态构造器
`ArchiveState`，口径只有一处。

术语详情必须先确认术语存在、再查文章。否则「拼错的 slug」与
「该术语下暂无文章」都会渲染成同一个空列表，读者分不清是自己点错了
还是站点真的空 —— 与「未知文章返回 40403」是同一条理由。

## 4. 一个必须绕开的框架陷阱

`PageSystem` 只按 `page.json` 的 `layout` 字段，在 `render.layout` 钩子里
给**正常响应**映射布局；该钩子对状态码 ≥ 400 的响应直接返回原布局
（为的是保留权限拒绝时的 `deny` 槽位）。

于是失败页如果只依赖清单映射，会落到默认的 `site` 槽位：
`site` 布局不认识 `sections` / `terms`，会把 422 / 404 / 503 渲染成
「带首页导航的空文章流」，错误说明一个字都看不到。

修法是 `ArchivePage::emit()` 在**所有**分支显式 `setLayout('archive')`。
守卫专门断言：未知术语返回 404 时，HTML 里仍必须出现
`data-layout="archive"` 与「术语不存在」。

## 5. 主题契约：成对提供，缺席时显式退化

两款元主题 `GlassFront` / `Glass` 成对新增 `archive` 布局：清单 `layouts`、
主题类的 `LAYOUTS`、模板、`archive.css` 四处同步，且 `archive.css` 逐字同源。
渲染器把归档字段统一收敛成模板变量，模板不直接翻 payload。

`Bare` / `BareHtml` **刻意不提供** `archive` 槽位。激活它们时，
`ThemeSystem` 放弃呈现权，核心退化为纯 JSON —— 这是规矩 J 允许且可判定的
降级（`Content-Type: application/json`），不是白屏，也不是一个空 HTML 壳子。
守卫分别断言两款元主题能渲染、非元主题退化为纯 JSON。

## 6. 实现中抓到的真问题

1. **失败态被甩回 `site` 槽位**（见第 4 节）。静态读代码看不出来，
   只有真实发出一个 404 请求、检查响应里的布局标记才会显形。
2. **隔离站点会 seed 两篇示例文章**。守卫一开始断言「共 2 篇」失败，
   查下来不是实现错了，是夹具没控制住初始状态。修法是前置里先把
   `first-post` / `second-post` 移入回收站，让总数由本夹具独占决定 ——
   否则「共几篇」这类断言会随机通过，比没有守卫更糟。
3. **守卫文件撞上职责跨度硬上限**。`38b` 同时沾 filesystem / http /
   rendering / security 四个职权域，触发规矩 H 的 `MAX_CONCERNS`。
   把 `Authorization` 字面令牌换成既有的 `adminHeaders()` helper 后降到三域。
   审计器在这里守住了自己：新增守卫也必须遵守单文件职责预算。
4. **标签云失败不能反噬主体**。首版若把 `content.terms` 的异常直接抛到外层，
   内存降级时整篇归档都会变成 503；改成旁路 `terms_state` 后，
   文章归档仍可读，且失败区域有明确说明。

## 7. 已知边界

- 归档用游标最多翻到硬上限，超出部分不在这页展示；需要全量遍历请直接用
  `content.posts` 的分页接口，页面不做无限滚动。
- 分组依据是 `created_at`，不是 `publish_at`：定时发布的文章按写作时间归档。
  站点主若需要「按上线时间归档」，规则加在独立页的分组函数里，不必改系统层。
- 术语链接依赖 `visitor_id` 之外无关的纯地址，匿名可读；点赞 / 举报等
  写操作仍需走接口与既有公网写边界，本轮不给主题开任何写路径。
- 归档与术语都只展示 `published` 且已到点的文章；草稿、回收站、未到点文章
  对读者就是不存在（与 `content.post` 的 `40403` 判定一致）。
- `core/` 未新增文件、未新增接口、未新增系统层、未新增核心契约；
  新增能力全部落在独立页、主题与守卫这三个承载层。
