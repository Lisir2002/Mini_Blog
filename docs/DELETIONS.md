# 删除闭环上后台（v0.46）

这一版补的是**两个「有能力、没入口」的删除动作**：`comments.delete` 与 `emojis.delete`。
它们不是同一类对象，但缺的是同一件东西 —— 一个能看清现状、能确认影响面、能解释结果的后台入口。

| 闭环 | 页面 | 读路径 | 写接口 | 页面层挡住的事 |
| --- | --- | --- | --- | --- |
| 评论删除 | `/console/queue`（扩成双视图） | `comments.queue` + `content.posts` → `content.post` → `comments.list` | `comments.delete` | 手写 id 确认、现场问 `comment.delete.any`、文章读不到 fail-closed |
| 表情管理 | `/console/emojis`（新建） | `emojis.list`（全量） | `emojis.register` / `emojis.delete` | 短码格式与占用、内置不可删、手写短码确认、`attachment_id` 正整数 |

零新增接口、零新增系统层、`core/` 零改动。两个页面声明的都是**读权限**，写动作在 Action 层现场裁决另一个权限点。

---

## 一、评论删除：队列之外也要能删

`comments.queue` 的口径是 **pending 待审 + 有任何举报**，且排除已删除。一篇正常文章下的已发布评论根本不在队列里 ——
如果只在队列条目上加删除按钮，删除能力仍然只覆盖「被举报的那几条」。所以 `/console/queue` 扩成两个视图：

- **① 审核队列**：原有状态迁移（published / hidden / spam）+ 每条一个删除表单；
- **② 按文章浏览评论**：从 `content.posts` 选文章 → `content.post` 复核 → `comments.list` 列出该篇评论（含 `deleted` 占位）→ 逐条删除。

这是附件库、资源 ACL、分类与标签之后，「选中某篇文章」这条浏览路径的第四次复用。

### 软删是终态，不是「隐藏」

`comments.delete` 清空 `body` / `author`，但保留 `path` / `parent_id` / `root_id`，子回复仍显示在「该评论已删除」下。
`CommentPolicy` 的状态机把 `deleted` 定为终态：既不能迁入，也不能迁出 —— 对已删除评论调 `comments.moderate` 返回 `40901`。
页面把这句话写在表单说明和结果回显里，不写「已删除」了事。

### 接口返回 200 不等于「这次删了」

| 返回 | 页面回报 | 含义 |
| --- | --- | --- |
| `deleted=true, already=false` | **已软删** | 这次真的清了正文与署名 |
| `deleted=false, already=true` | **本来就已删除** | 幂等：不报错，也没有重复写库 |

一律说「已保存」会把幂等说成新写入，一律说「失败」又会让人反复重试。

### 授权顺序与页面层二次裁决

`CommentPolicy::canDelete()` 先看 `comment.delete.any`，再看「本人 + `comment.delete.own`」；匿名评论没有主人，只能走前者。
但**审核页是删别人的评论**，所以页面层只认 `comment.delete.any`：票据绑的是页面级 `comment.moderate`，
Action 必须现场再问一次 `AccessControlInterface::allows($identity, 'comment.delete.any')` —— 页面直调 `execute()` 会绕过 API 分发器，
不在页面层裁决就等于把删除权交给任何能进这个页的人。`comment.delete.own` 是前台删自己评论的入口，本页刻意不提供，
边界说明里写清楚，避免「看得到却点不动」变成猜谜。

删除还要求**手写评论 id 确认**：终态不可恢复，误点一次就回不来。

### 一个真实的字段陷阱

`comments.list` 的 `present()` 对已删除占位仍返回 `deletable=true`（因为 `canDelete()` 只看权限，不看状态）。
页面不能只靠 `deletable` 决定给不给按钮，必须同时判断 `status !== 'deleted'`，否则会对占位再渲染一个删除表单。

## 二、表情目录：内置不可删，自定义只认本站附件

`emojis.list` / `emojis.register` 此前只在 `tools/journey/ContentStage.php` 里被消费，后台没有管理页。
新建 `/console/emojis` 把三个接口接成闭环：列目录 → 登记自定义图片表情 → 按短码删除。

### 目录一次取全量，筛选只作用于展示

`emojis.list` 支持 `kind` 过滤，但页面**不传**：短码占用预查必须基于完整目录，
按 `kind` 过滤后再判「这个短码有没有被占用」会漏掉内置表情，接口随后抛 `40901` —— 页面能提前说清的事不该甩给接口。
类型筛选在页面层对已取回的全量做，目录没有分页参数，`total` 就是全量。

### 存原文、渲染时解析

`emojis.delete` 不会重写历史：正文里存的是 `:shipit:` 字面量，解析发生在渲染时。
删掉表情后读者仍看到字面量，只是不再渲染成图片。这是「存原文」相对「入库即替换」的关键收益，
页面在删除表单与结果回显里都写明，不让管理员误以为要清理旧文章。

### 同一个 `40403`，两种含义

| 动作 | `40403` 的真实含义 | 页面文案 |
| --- | --- | --- |
| `emojis.register` | 引用的附件不存在（或已删除、不是 `image/*`） | 「引用的附件不存在：请核对附件 id」 |
| `emojis.delete` | 自定义表情不存在 | 「自定义表情不存在：可能已被别人删掉」 |

照搬接口原文会让人去错地方找原因。`emojis.register` 只接受本站图片附件 id，不接受 URL ——
外链表情会让每次浏览都向第三方发请求，也能被随时替换。页面层先校验短码语法（2–32 位小写字母 / 数字 / `_ + -`）、
占用与 `attachment_id` 为正整数；附件存在性没有「按 id 查单个附件」的只读接口，交给接口裁决并翻译。

内置表情 `custom=false` 根本不生成删除按钮，页面层也拦住 `40901`；删除自定义表情要求**手写短码确认**。

## 三、两个页面共用的三条规矩

**读写权限分离。** 页面声明 `comment.moderate` / `content.read`；写动作分别现场问 `comment.delete.any` / `emoji.manage`。
守卫只证明「谁从哪一页提交」，票据不替代写权限裁决。`62` / `63` 组各自用 `revoke('*') + grant(读权限)` 验证：
GET 仍 200，写提交 403 且点明缺哪个权限点。

**「空」有好几种，不是一种。** 队列为空 / 队列读失败 / 被截断、文章读不到 / 文章确实没有评论、`deleted` 占位、
目录为空 / 目录读失败 —— 都分开表达。文章读不到时 fail-closed：不说「没有评论」，并关掉对应写入口，
避免把「不知道」渲染成可以去清空的空集合。

**成功 303、失败不跳转且回填。** 只有 `saved` 参数存在才显示提交结果，普通 `?view=` / `?kind=` 导航不误报。
失败态自己固定 admin 布局，否则 4xx 会被渲染成带门户导航的空页面，错误说明一个字看不到。

## 四、测试与边界

`62` 组 10 项：匿名与默认页、队列条目双表单、缺确认 / 未知 op、软删 303 与回复链占位、
幂等 `already`、终态再审核 `40901`、按文章浏览、文章读不到 fail-closed、权限隔离、方法边界与回填。
`63` 组 10 项：内置目录与类型筛选、非法短码 / 附件 id、附件不存在 `40403` 翻译、登记 303 与预览链接、
重复占用、内置 / 缺确认 / 不存在三类删除拦截、删除 303 与不重写历史、权限隔离、方法边界与回填。
两组各用一份隔离站点，权限隔离必须在同一份已落库数据上验。

边界：不做批量删除、不改历史正文、不做短码改名；文章窗口 20 篇 / 评论窗口 60 条 / 表情目录 120 条上限，
都不是完整快照；`comment.delete.own` 路径刻意不进后台；`permission.override.grant` 与其余运维面接口按设计仍留在零消费清单。
