Architecture Overview · v0.60

Mini Blog

核心只做装配与调度；一切能力是系统层，一切呈现是承载包，一切交互是接口，一切单元的装卸由元层管辖。删光所有系统层与包，框架仍能启动——只是什么都不做，且一个字节的样式都不会输出。

第一性原理：高度自定义，万象皆接口
纯原生 PHP · 无模板引擎 · 无第三方框架
建议全数采纳 · 18 系统层 · 92 接口

五条可验证的硬约束

口号会退化成「加个配置项吧」，所以这里把它拆成有测试守卫的约束；另有规矩 F / G 同样带守卫。

H1

零呈现

核心永不产出 HTML / CSS / JS。未接入主题 → 全站零样式。静态扫描 + 运行时断言双重守卫。

H2

零业务

不写 SQL、不建表、不内置任何路由与默认页面。首页本身也是独立页包。核心文件数钉在 24 以内。

H3

一切可换

能力通过契约绑定，实现可被显式替换并留痕；同级冲突直接报错，不搞静默覆盖。

H4

纯原生栈

禁 Twig / Blade / Smarty、composer / vendor、任何 PHP 框架与 ORM；模板就是原生 .php。

H5

操作皆接口

每项操作规范化为接口，一个接口对应一份规范化文档，清单驱动、守卫阻断漂移。

五层模型（元层 + 18 个系统层，最新为第 18 层 metric）

层间只允许通过接口通信，不允许跨层直接 new 具体类。核心甚至不知道「文章」「升级」这两个词的存在。

L3表现与内容
主题包 themes/*（Bare 带样式 / BareHtml 零 CSS） 插件包 plugins/* 独立页包 pages/*（可 standalone 自带 CSS/JS）
三者共用同一身份：PackageInterface。后台 UI 是 pages/Console 可卸载包；是否套用站点主题由独立页清单的 standalone 决定。
L2承载型系统层
主题系统 → RendererInterface 插件系统 独立页系统 → render.should_render 裁决
只负责「装载包」，自身不产出任何内容、不渲染一个标签。
L1能力型系统层
日志用户安全 评论数据库权限（第 12 层） 内容（第 11 层）成员（第 13 层）版本（第 14 层）API 接口…未来任意新系统
全部实现 SystemInterface，与官方系统完全对等；新增 = 丢目录 + 写 system.json，内核零改动。实测 14 层顺序：log → data → security → lifecycle → user → permission → api → plugin → member → content → release → theme → comment → page。
LM元层 · 装卸系统
install / activate / deactivate upgrade / rollback / uninstall / verify HMAC-SHA256 签名验签
管理五类单元（core · system · theme · plugin · page）的生命周期；对外只暴露 LifecycleManagerInterface。状态机 + 暂存区 + 升级备份 + 失败自动回滚 + 版本对账。
L0系统核心
KernelContainer HookBusSystemRegistry PackageLoaderRouter
24 个 PHP 文件，其中 13 个契约接口（已达上限）；0 个 CSS/JS、0 条 SQL。黑名单：任何 HTML/CSS/JS、表、路由、模板、后台 UI、模板引擎与第三方框架。

「万象皆接口」= 五张接口网

契约面

Container

13 个契约，实现可替换；接上 MySQL 走 PDO，拔掉库自动回退内存适配器。

事件面

HookBus

流程可拦截：action 广播、filter 链式改值，priority 升序。

装配面

*.json 清单

单元可插拔：系统层、主题、插件、独立页统一清单驱动。

数据面

DatabaseInterface

29 张业务表与 SQL 归各系统层自持；连接 / 事务 / 观测 / 巡检归 data 层；无主题时整站即 JSON API。

接口面

registry.json

92 个接口，一个 operation 一个执行者，一个接口一份文档 + OpenAPI 3.1。

无主题零样式：结构性保证，而非口头约定

API 接口系统 · 一个接口一份文档

唯一事实源

api/registry.json

92 个接口，逐条声明路径 / 方法 / 参数 / 错误码 / 幂等性 / 副作用 / 文档路径；ID、路由、operation 三者全局唯一。

统一信封

code · data · meta

code/message/data/request_id/meta；14 个错误码前两位对齐 HTTP 状态；禁止「200 里塞错误」。

1:1 文档

39 份 API-*.md

清单 + 模板 → tools/gen-api-docs.php；另有 export-openapi.php 导出 3.1；守卫阻断漂移，禁止手写。

分发顺序：匹配接口 → 429 限流 → 写接口公网边界 → 鉴权执行 → 参数校验 → 幂等去重 → 唯一 operation → 统一信封。鉴权刻意排在参数校验之前；身份以 _identity 注入业务执行者。规范借鉴 OpenAPI 3.1 / RFC 9457 / Azure REST / Google AIP / Zalando / Stripe，全部自研实现。

v0.4 → v0.20：落地清单

内容

第 11 个系统层 content

契约 + MySQL 实现 + 自有 migrations + 生命周期钩子 + 4 个接口；keyset 游标分页；内核零改动，是对可扩展性的真实检验。

数据

MySQL 全量实现

用户 / 评论 / 内容从内存占位换成 PDO 实现，真实建立 5 张表并读写；拔掉 DSN 自动回退，框架仍可启动。

安全

鉴权从声明变执行

令牌落库只存 SHA-256 摘要、带过期与撤销；40101 / 40102 / 40301 / 40302；CSRF 落库一次性；CSP 可配置。

接口

幂等 · 限流 · 分页 · OpenAPI

Idempotency-Key 服务端去重、429 + Retry-After、游标分页、由清单导出标准 OpenAPI 3.1 文档。

承载包

后台与独立页

可卸载控制台、工具页、只读安装向导、零 CSS 的 bare-html 主题；v0.6 起全部改由主题提供布局，独立页不再持有任何 CSS/JS。

定案

命名 / 版本 / 冲突策略

「Mini Blog」Wx\（保留的历史命名空间）、v0.60.0、PHP ≥ 8.1；保留显式 priority + fail-fast + 留痕；包签名验签（HMAC-SHA256）落地。

规矩 H

单文件职责预算

行数 / 责任主体 / 扇出 / 职权跨度四指标分层预算，audit-responsibility.php 静态审计。上帝类 563 行 → 188 行编排者 + 7 个协作者。

规矩 I

协作全方位验证

8 类协作矩阵 C1–C8 + 存在性 / 一致性 / 运行时贯通 / 故障注入四维；C9 断言每一类都有实际跑过的守卫。

规矩 J · v0.6

呈现权完全归主题

后台布局同样过主题系统。独立页只产数据 + 声明 layout 槽位，主题包持有 site / admin / tool / install 全部模板与 CSS/JS；主题缺某布局 → 该页退化为纯 JSON，框架绝不兜底。standalone 绕过主题的后门已拆除。

规矩 K · v0.6

权限系统（第 12 层）

用户权限 RBAC / 文章权限资源 ACL / 系统权限各层自报；决策三态 allow·deny·abstain、fail-closed、策略钩子只能收紧不能提权、每次决策留痕。49 个权限点、14 个权限接口（API-PERM-001~014）、9 张权限表（全站 24 张）。

v0.7 深化

继承 / 缓存 / 字段级

角色继承用 permission_role_parents 边表 + 决策时展开，自环 / 成环 / 深度超限写入即拒；决策缓存只缓存基础读取、绝不缓存最终决策，授权变更显式失效；ACL 新增 field 维度，精确拒绝某字段而不剔除整篇。core/ 仍 24 个 PHP。

v0.8 规矩 L

页面权限 / 覆盖鉴权

5 个页面在 page.json 声明分级 access，route.access 统一裁决并短路；与 API 共用认证器与权限决策器，策略钩子只能收紧，拒绝页样式归主题 deny 布局。契约覆盖新增授权台账：require_grant 开启后未授权覆盖 fail-closed，授权必须经运行时身份。core/ 未新增文件。

v0.9 规矩 M

主体可扩展 / 凭据单一来源

用户组只作「角色来源」，主体角色集合 = 自身角色 ∪ 组绑定角色，决策骨架与 deny 优先级一字未改；页面会话与 API 令牌同表同过期同撤销，只换 HttpOnly + SameSite=Lax 载体，且会话令牌不得当 Bearer 调普通 API；权限缓存新增可换后端（进程内 / 文件），以 epoch 换代失效；content.update 逐字段裁决、任一被拒整次拒绝，绝不部分写入；契约覆盖默认 require_grant=true，仅已注册系统层自动登记，plugin: / theme: / page: 必须运行时授权。core/ 仍 24 个 PHP。

v0.10 规矩 N

身份与授权解耦

第 13 系统层 member：站长自定义头衔（标识 / 颜色 / 权重 / 自动门槛）、经验规则（单次值 / 每日上限 / 启停）、等级门槛（任意级数与区间）。经验流水 append-only、event_key 幂等、上限截断、写流水与加余额同事务；等级是「经验 + 门槛」的解释结果，可重算、只升不降；头衔手动授予 ∪ 等级自动，零权限。用户组补颜色与排序，仍只是角色来源。core/ 仍 24 个 PHP。

v0.11 规矩 P

标准化安装 · 不重装迭代

五步安装向导（环境 / 数据库 / 管理员 / 迁移基线 / 加锁）只写 config/local.php 与 install.lock，写动作须带 0600 一次性令牌且仅本机来源，装完页面整体 404。第 14 系统层 release 用迁移台账 + checksum 校验 + 健康门禁把「升级 → 失败回退」做成一次可回滚事务；快照按版本归档、keep_releases 只裁最旧，可回退到任意装过的版本，回退前还给当前版本留一份。core/ 仍 24 个 PHP。

v0.13 规矩 R

内容互动（第 16 / 17 层）

评论升级为树：邻接表 + 物化路径、深度上限拒绝而非改挂、tombstone 软删保住子回复、审核状态机白名单。附件元数据入库、字节按 SHA-256 内容寻址，文件名不进路径，四道类型校验；上传下载复用同一套 RequestGuard，下载每次授权。表情只产出 token 不产 HTML，自定义只引用本站附件，删除不改写历史。core/ 仍 24 个 PHP。

v0.14 规矩 S

数据层（第 8 层原位升级）

不新增第 18 层，而是把 database 升级为 data：显式 sql_mode 严格模式、DataSession 事务 / 嵌套 savepoint / afterCommit、QueryProfiler 查询计数、关系登记 + 只读孤儿巡检。表情 findMany / parseMany 消除 N+1，评论写入事务包裹、出站显式白名单、父隐藏则整枝隐藏。规矩 S「数据三不」把三道边界固化成守卫。容器 18→22 个注册项，系统层仍 17 个、core/ 仍 24 个 PHP、业务表仍 24 张。

v0.15 规矩 T

性能治理：核心不设计性能强化系统

「动态分配核心 / CPU 调度 / 线程调度」按三问法三条全不成立，属部署层与内核；PHP 每请求重建内核、worker 归 FPM、线程归调度器，本机 nproc=32 而 cgroup 配额 4 核，按可见核数调核只会抢配额。服务器参数写成部署清单不进代码；core/ 零改动、系统层仍 17。可选增强包 plugins/Performance/ 默认关闭，只做 ETag / 304 / gzip、Server-Timing 与预算留痕。php tools/bench.php 实测：60 请求传输字节 190,908 → 26,450（−86.1%），SQL 条数 2,520 → 2,520；4 并发 worker 1 核 → 4 核 970.16 → 343.08 ms（2.83×），钉在固定 4 核反而比放开可见核慢。规矩 T「不越界 / 不猜 / 不隐形」由 3 组守卫 10 项断言守着。

Glass · 半透明磨砂玻璃后台

v0.19 收敛期

v0.12 规矩 Q

状态系统（第 15 层）

五态 pending / running / waiting / done / failed，等待与交互由 held_by=system|user 区分；每个状态带说明、出路、证据三件套。长任务落 state_tasks，revision 乐观锁、终态不可逆；未捕获异常经 kernel.exception 走同一套主题渲染；文案键可覆写，可访问性归主题。core/ 仍 24 个 PHP。

仍需注意的边界：控制台为只读 + 令牌查询原型；匿名评论已有审核状态机，但仍需验证码与速率型风控；演示账号 admin/admin123 与配置中的明文口令 / 空签名密钥仅用于本地原型，投产前必须删除、改密并由环境注入；限流与幂等缓存基于文件存储，多实例部署需换共享存储。权限系统剩余边界：用户组不支持嵌套（等价能力已由角色继承提供）、缓存跨主机共享未做（换 Redis 只改后端实现）、会话无多设备管理界面、字段级写目前只作用于 content.update。require_grant 已默认开启，迁移存量站点前须先对账登记合法覆盖。成员系统剩余边界：经验流水无归档、排行榜为 limit/offset（榜单变动时会漏行或重行）、等级变更不回溯通知、/console/member 的写操作不做批量 / 不做影响面预览 / 定义删除不清理已落库的授予关系、头衔不参与权限是刻意设计。core/ 已达 24 个 PHP 上限。包仓库协议、多站点、契约版本协商列入 v1.0。
本页是架构说明文档，样式内联于此 HTML；框架里 core/ systems/ pages/ plugins/ 均不存在任何 CSS/JS 文件——样式与脚本只存在于 themes/（规矩 J）。代码全数自研：借鉴 WordPress 的 Hook 模型与包生命周期、Typecho 的轻量思路、Halo 的动态装卸，以及 OpenAPI 3.1 / RFC 9457 / Azure REST / Google AIP / Stripe 的接口规范，但全部用原生 PHP 实现，未引入任何模板引擎或第三方框架。
