# 订阅与收录

`/feed`、`/sitemap.xml`、`/robots.txt` 三个地址此前都不存在：站点不能被阅读器订阅，
也不能被搜索引擎完整收录。

## 这不是「加三个文件」

本项目的边界是「`pages/*` 只产结构化数据，格式由主题决定」。RSS 是 XML ——
让主题渲染 XML 会破坏「主题只管站点外观」的直觉：一旦允许主题改结构，
阅读器就会解析失败，而失败发生在读者的客户端，站点这边什么都看不到。

v0.33 的解法是给「非 HTML 响应」定一条明确路径：

| 角色 | 职责 |
| --- | --- |
| 页面 | 声明响应类型，直接产出协议文档（XML / 纯文本） |
| 渲染器 | 布局槽位为 `raw` 时找不到模板，**原样放行**，不包 HTML 骨架 |
| 主题 | 完全不参与；不需要为 RSS 增加任何模板 |

`raw` 不是新布局，只是「主题不认领这个槽位」的显式写法。附件下载早已用同样的方式
绕过主题（`binary`）。协议文档与站点外观从此不再互相污染。

## 三个文档

| 地址 | Content-Type | 内容 |
| --- | --- | --- |
| `/feed` | `application/rss+xml` | 最新 20 篇已发布文章：标题、绝对链接、`pubDate`、摘要 |
| `/sitemap.xml` | `application/xml` | 首页 / 归档 / 标签 + 最多 500 篇已发布文章 |
| `/robots.txt` | `text/plain` | 允许抓取，挡住 `/console` 与 `/install`，声明 sitemap 绝对地址 |

口径与归档、搜索一致：只含 `status=published`，定时未到点的不出现。
草稿进 RSS 意味着读者能看到未完成的内容；草稿进 sitemap 意味着搜索引擎会提前收录。

## 绝对地址从哪来

订阅源与站点地图里的链接必须是绝对地址（相对地址在阅读器里无法解析）。
优先 `config.site.url`；未配置时按请求头推断：`Host` + `X-Forwarded-Proto`
（反向代理后是 https）。推断而不是写死，是为了本地、预览、生产三处都能用同一份代码。

## 失败不是「没有文章」

取数失败返回 **503 + 纯文本原因**，并明确写「这不是本站没有文章」。
一份空 feed 会被阅读器缓存成「这个站没有文章」，比报错更难发现、更难纠正。

## 证据

- `48` 组：XML 结构（声明 / 转义 / 配对）、绝对地址、草稿排除、Content-Type、
  失败语义、响应里没有 `data-layout`（证明没被主题包成 HTML）。
