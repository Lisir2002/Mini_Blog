# 站内搜索

`/search?q=` 是内容发现闭环的第二条路：归档按时间翻，搜索按词定位。
两者都不新增接口 —— 搜索只是把 `content.posts` 早就支持的 `keyword` 接到页面上。

## 为什么单独一页

归档页也能带筛选参数，但把它扩展成搜索会混淆两种状态语义：归档没有「还没输入」这个状态，
搜索有。一旦混在一起，「未输入」与「没搜到」迟早被写成同一张空列表 —— 那正是
本项目一直在防的「安静地错」。

## 四态必须可区分

| 状态 | HTTP | 呈现 | 判据 |
| --- | --- | --- | --- |
| 未输入 | 200 | 「输入关键词开始搜索」+ 表单 | `q` 为空 |
| 没有匹配 | 200 | 「没有匹配的文章」+ 归档 / 标签出口 | `total = 0` |
| 有结果 | 200 | 「共 N 篇命中」，被截断时声明「本页只列前 M 篇」 | `total > 0` |
| 不可用 | 503 | 失败原因 + 「这不是没有结果」 | 取数抛错 |
| 关键词过长 | 422 | 说明上限与实际长度 | 超过 80 字符 |

非法输入不静默截断：截断后的结果与用户输入不对应，比直接拒绝更难排查。

## 通配符不是语法

`PostQuery` 此前把用户输入直接拼进 `LIKE '%...%'`。搜一个 `%` 会变成通配符，
返回全站文章；搜 `_` 会匹配任意单字符。v0.33 起对 `\`、`%`、`_` 做转义，
并显式声明 `ESCAPE`（不依赖服务端 `sql_mode`）：

```sql
title LIKE :kw_title ESCAPE '\'
```

内存实现用的是字面量 `str_contains`，转义后两套存储的行为才真正一致 ——
此前「MySQL 把 `%` 当通配符、内存把它当字符」正是同一能力两种语义的典型分裂。

## 契约

- 页面：`pages/Search`（`SearchPage` / `SearchQuery` / `SearchBlocks`），只产结构化数据。
- 布局：复用 `site` 槽位，区块类型为 `form`（GET）、`notice`、`list`。
  `list` 的条目可以是纯文本，也可以是 `{label, href, note}` —— 搜索结果需要标题即链接，
  纯文本行保持原样，向后兼容。
- 数据：只取 `status=published`；草稿、定时未到点、回收站不会从搜索漏出去。

## 证据

- `php tests/run.php` 的 `45` 组：四态区块互不相同、表单是 GET、转义与页面纯度；
- `45b` 组：隔离站点上真实请求 —— 未输入 / 命中 / 未命中 / `%` 字面量 / 超长 422。
