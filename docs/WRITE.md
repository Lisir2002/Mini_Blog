# 写文章

`/console/write` 是内容闭环的最后一段。v0.34 之前，后台能看列表、能迁移状态、能进回收站，
但站上没有一个地方能写正文：`content.create` 只被旅程脚本调用，`content.update` 零消费。

## 1. 路由与模式

| 地址 | 模式 | 消费的 operation |
| --- | --- | --- |
| `/console/write` | 新建 | `content.create` |
| `/console/write?slug=…` | 编辑 | `content.post`（读）、`content.update`（写） |

新建与编辑共用一个页面，因为字段、校验、票据、失败呈现完全一致；分开只会让两份实现漂移。
表单里有一个隐藏的 `mode=create|edit`：**新建也允许自定义 slug**，所以不能用「slug 是否为空」
推断模式 —— 早期版本正是这样推断的，结果自定义 slug 的新建被当成更新，返回 404「文章不存在」。

## 2. 状态机在按钮上

表单没有下拉框，只有两个提交按钮：

- `保存草稿` → `status=draft`
- `发布` → `status=published`

按钮把「这次要变成什么」写在动作上。下拉框的默认值在零脚本环境里更容易被误读成「已经发布」。
状态缺失或不在白名单内一律 422，**绝不默认成发布，也不静默当草稿**。

## 3. 权限边界

页面声明 `auth=admin` + `permission=content.create`，因为 `content.create` 接口本身就是
`auth=admin`。作者角色虽然拥有 `content.create` / `content.edit` 权限点，但接口的 `auth=admin`
先把人拦住了 —— 这是契约层的事实，页面不偷偷放宽。

编辑时 `content.update` 会逐字段询问 `content.edit` 的字段级 ACL；某个字段不允许就整次拒绝，
不存在「标题改了、正文没改」的部分成功。`author` 只在新建立时取自当前身份，表单不能填写，
避免冒名。

## 4. 写路径

1. GET 签发票据，绑定 `content.create` + `/console/write` + 20 分钟；
2. POST 由守卫验签（非 GET 仍不读 Cookie），页面拿到身份后调用接口；
3. 成功：`303` 回 `/console/write?slug=…&saved=created|updated`；
4. 失败：`4xx` 留在原页，**正文原样带回表单**，不跳转、不清空。

失败不 303 的理由与登录页相同：303 表示「去看另一个地址」，而失败必须留在原地解释原因。

## 5. 失败语义

| 场景 | HTTP | 业务码 | 页面表现 |
| --- | --- | --- | --- |
| 标题为空 | 422 | 42201 | 「标题不能为空」，正文保留 |
| 标题超过 200 字符 | 422 | 42201 | 写明当前长度，不静默截断 |
| 状态非法 | 422 | 42201 | 列出允许的 draft / published |
| slug 重复 | 409 | 40901 | 「slug 已被占用」，不覆盖已有文章 |
| 文章不存在 | 404 | 40403 | 不渲染编辑表单，只给返回入口 |
| 字段级写被拒 | 403 | 40303 | 写明哪个字段被拒 |
| 正文进回收站 | 409 | 40909 | 提示先恢复 |
| 数据库不可用 | 503 | 5xxxx | 读不到时明确「读取失败」，不显示空表单 |

## 6. 不做的事

- 不做所见即所得编辑器：正文以 `textarea` 原样提交，系统里没有 HTML 白名单，
  前端富文本只会把「谁负责清洗」这个问题留到以后；
- 不做自动保存：没有版本表，自动保存会制造「以为存了其实没存」的错觉；
- 不做并发乐观锁：`content.update` 目前是最后写入者获胜，两个人同时改同一篇会互相覆盖；
  要补需要版本列与冲突响应，属于契约变更；
- 不做分类 / 标签绑定：`content.attach` 与 `content.terms.manage` 仍零消费，留给独立的术语页；
- 不做预览：预览需要「未发布内容对匿名可见」的临时授权，风险高于收益。

## 7. 验证

```bash
php tests/run.php                 # 51 组：草稿 / 发布 / 失败保留正文 / 权限 / 冲突
php tools/consumers.php --zero    # content.create / content.update / content.post 已离开零消费
php tools/facts.php verify
```
