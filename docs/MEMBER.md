# 成员成长页（`/console/member`）

> 只读视图，消费 `member.levels` / `member.titles` / `member.xp.rules` / `member.leaderboard` / `member.profile`。
> 它同时修掉了两个「自洽但错误」的数：排行榜的 `total` 与不存在的数字 ID 拿到的假档案。

## 1. 为什么是只读

成员系统从 v0.10 起就有十个接口，页面一个都没调过。等级表、头衔目录、排行榜在站点上完全看不见 ——
读者不知道自己为什么是 Lv.2，站长不知道自己定义的头衔还在不在。

这一版只补**看见**，不补**改**。三件写事的复杂度不在表单，而在语义：

- 发经验：同一次点击重复提交会重复加分（`event_key` 由谁生成？），没配规则时必须显式 `amount`；
- 授头衔：档案在、账号不在时该给谁挂牌？撤销要不要连带回收等级自动头衔？
- 改等级 / 改规则：改门槛会让所有人的等级「下一次读取时」变，要不要先算影响面？

每条都值得单独一版，塞在一起只会每条都做不干净。

## 2. 接口语义（v0.41 修正）

### 2.1 `member.leaderboard`

| 字段 | 含义 | 易错点 |
| --- | --- | --- |
| `total` | **有成长档案的成员总数** | 原先返回本页条数（`array_slice` 之后 `count()`），拿它写「共 N 人」永远成立且不报错 |
| `returned` | 本页返回条数 | 与 `total` 一起看才知道看的是第几页 |
| `has_more` | 后面还有没有下一页 | 分页界面需要的是这个，不是自己拿两个数去减 |
| `next_offset` | 下一页的 offset，没有则 `null` | 页面直接用它拼链接，避免各页面自己算上限 |
| `items[].orphan` | 该条目解析不到账号 | 账号被删，或档案是按 `user_id` 直接写入的 |

修掉的实现：

```php
$items = [/* ... */];
return ['items' => $items, 'total' => count($items)];   // 本页条数冒充总数
```

`count()` 现在来自存储协议（`ProfileStoreInterface::count()`，PDO 走 `SELECT COUNT(*)`，内存实现走数组长度），
与 `leaderboard()` 同表同口径 —— 两个数各算一套是下一处漂移的来源。

### 2.2 `member.profile`

原先只对**非数字**标识返回 `40403`：

```php
if ($user === null && !ctype_digit($identifier)) throw new ApiOperationException('用户不存在', 40403);
```

于是 `?user_id=999999` 走进「按 ID 直接组装」的分支，返回 `xp: 0 / level: 1 / username: ""`，HTTP 200。
这不是「显示不准」：一份看起来正常的空档案会让人以为这个人真的存在，进而给他发经验、授头衔 ——
而 `member.xp.award` 确实不校验账号存在，库里就多一条没人能认领的档案，榜单上多一个空名字。

现在：**用户与档案都查不到**才 `40403`；档案在而账号查不到，返回档案并置 `orphan: true`。
读路径收紧、写路径放宽是刻意的 —— 界面不能把人指错，但插件可以给站点外主体记账。

## 3. 权限：补一个缺失的读权限点

成员层自报的五个权限点全是写（`member.xp.award` / `member.xp.rule.manage` / `member.title.manage` /
`member.title.grant` / `member.level.manage`）。一个「只读成长视图」只有两条路：借写权限点（等于说「能看 = 能发」），
或者不声明（审计时看不出这一页归谁）。

v0.41 补 `member.read`（48 → 49 个权限点），与大三层的 `user.read` / `permission.read` / `logs.read` 对齐。
**接口不跟着收紧**：等级表与头衔目录本来就该对读者公开，改成「要权限才能读」会造出
「站点上看得见、接口里读不到」的悖论。经验规则例外，它按 `member.xp.rule.manage` 裁剪。

页面**先问决策器、再决定调不调**：

```php
$can['rule'] = $acl->allows($identity, 'member.xp.rule.manage');
if ($can['rule']) $out['rules'] = self::call($registry, 'member.xp.rules', [], ...);
```

调了再吞 403 会把「你没权限」与「接口坏了」混成同一句失败。

## 4. 四种「没有」必须分开

| 状态 | 触发条件 | 页面呈现 | 为什么不能合并 |
| --- | --- | --- | --- |
| `empty`（榜） | `total = 0` | 「还没有人获得经验」+ 解释榜单只含有档案的人 | 说成「站点没有成员」是错的：账号在 `/console/users` |
| `permission-denied` | 无 `member.xp.rule.manage` | 「看不到经验规则」+ 明说「这不等于没有规则」 | 把「看不到」读成「没有」会让站长去建重复规则 |
| `unconfigured` | 等级表为空 | 「等级表是空的」+ 说明所有人会被解释成 Lv.1 | 空表时页面一切正常，没人能升级也没有报错 |
| `inconsistent` | 等级跳号 / 门槛重复 | 「等级表有断点」+ 指出缺哪一级 | 接口层认为合法，成员却会卡在同一档 |
| `unavailable` | 接口抛错 / 成员层停用 | 逐块降级，错误原文照给 | 读不到不能长得像「没有」 |

## 5. 页面结构

1. **范围说明** —— 这一页只读，写操作不在这里；
2. **等级表** —— 档位 / 门槛 / 颜色，附断点告警；
3. **头衔目录** —— 显式 `include_hidden=1`，隐藏项标「隐藏」并计数；
4. **经验规则** —— `+50 / 次 · 每日上限 200 · 说明`；`daily_cap = 0` 显示成「不限（0）」，因为 0 在接口里是「不限」而不是「不给」；
5. **排行榜** —— 名次窗口（第 a–b 位 / 共 N 位）、上/下页、`orphan` 行标「账号已删除，档案还在」；
6. **单人档案** —— GET 表单查 `?user=`，查不到说「用户不存在」，不再编造档案；
7. **出口与边界** —— 去用户 / 角色 / 决策 / 内容，以及榜单口径与分页口径。

## 6. 只读与写方法

没有 `form_ticket`。带 Cookie 的 POST 在守卫层就是 401（Cookie 不参与写，v0.9 起的 CSRF 边界），
带 Bearer 的 POST 才走到页面自身，返回 `405` + `Allow: GET, HEAD`。

## 7. 测试

`tests/groups/57-member-runtime.php`（14 条）：

- 匿名 401；管理员 GET 五块齐全，空榜文案正确且不渲染 0 人排行表；
- 接口语义：空榜与有数据时 `total` / `returned` / `has_more` / `next_offset` 四项分别断言；
- 翻页窗口「第 3–3 位 · 共 3 位」与「这已是最后一页」；
- 参数错：`offset=abc` / `offset=99999` 均 422，文案带上限；
- 头衔：隐藏项在页面上、不在公开接口的默认响应里；
- 查无此人：`t57-nobody` 与 `999999` 都 40403，页面不渲染档案；
- 档案：正常账号显示名 + 用户 ID；有档案无账号时明说「查不到账号」；
- 等级断点：删掉 Lv.2 后页面指出「缺少 Lv.2」，测试结束恢复；
- 权限裁剪：只留 `member.read` 时页面仍 200，但规则块说「看不到」且不渲染 `post.publish`；
- 只读：Cookie POST 401、Bearer POST 405 + `Allow`；
- 成员层停用：页面仍 200，逐块声明「不可用」并给出原因。

测试在 `/tmp` 隔离站点 + 独立表前缀里跑，结束不触碰工作区的 `wx_` 表。

## 8. 边界

- 不做写：发经验、授头衔、改等级与规则都不在本页；
- 不做经验流水：流水在 `member_xp_events`，接口没开；
- 不做游标分页：榜单变动时 offset 会漏行或重行，已在页面上写明；
- 不做头衔与权限的联动：头衔不产生任何权限，这是 v0.10 起的刻意设计。
