## 2. 功能与适用场景

列出全部分组、每组绑定的角色与成员，用于排查「某人为什么有这个权限」。

**适用场景**：后台权限页展示用户组；排查组成员关系导致的授权来源。

**实现备注**：只读接口。组只是角色来源：成员通过组获得的角色与自身角色取并集，不复制授权表。拔库回退时返回空图并带 fallback 告警。 0.44.0 起 /console/acl 的用户组面板列出组 / 角色 / 成员，并用 users.view 查账号辅助填写成员主体。

  "message": "ok",
  "data": {},
  "request_id": "16 位十六进制",
  "meta": {"api": "API-PERM-013", "version": "v1", "system": "permission"}

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | int | 业务码，`0` 为成功；非 0 为可分支的机器可读错误码 |

| `data` | any | 成功时的业务数据；失败时恒为 `null` |

| `detail` | string | 仅当 `config.api.expose_errors=true` 时出现，禁止在生产开启 |
| `meta` | object | 接口编号、版本、所属系统层 |

**data 字段说明**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `groups` | `object` | group_key → {group, name, description, roles, members} |

## 5. 错误码

| 业务码 | HTTP 状态 | 说明 |
| --- | --- | --- |
| `40101` | 401 | 未认证 |
| `40102` | 401 | 令牌无效或已过期 |
| `40301` | 403 | 无权限执行该操作 |
| `40302` | 403 | 写接口未开放公网访问 |
